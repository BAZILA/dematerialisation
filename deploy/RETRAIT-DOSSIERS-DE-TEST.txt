=======================================================================
  1. CE QUE FAIT CETTE MIGRATION
=======================================================================

  EFFACE
    - les dossiers (student_requests), tous statuts confondus ;
    - en cascade : les pieces deposees, les etudes anterieures saisies,
      les derogations ;
    - les paiements declares sur ces dossiers ;
    - les notifications envoyees au sujet de ces dossiers ;
    - les FICHIERS de ces pieces sur le disque, originaux ET versions
      tamponnees.

  NE TOUCHE PAS
    - les COMPTES : etudiants, agents, administrateurs. Personne n'a a
      se reinscrire, les codes d'acces restent valables ;
    - les fiches du referentiel et leur marque « inscrit » — le compte
      existe toujours, la marque reste donc juste ;
    - la CONFIGURATION : pieces attendues par grade, procedures,
      periodes, annees, facultes, parcours, parametres, roles ;
    - le cachet, les signatures, les gabarits, les sauvegardes ;
    - le journal d'audit ;
    - les candidatures publiques (voir le reglage en section 3).

  RESULTAT
    A sa prochaine connexion, chaque etudiant retrouve l'ecran de
    depart et le bouton « Creer mon dossier ».


=======================================================================
  2. COMMENT LES FICHIERS SONT CHOISIS
=======================================================================

  La migration releve le chemin de chaque piece AVANT de supprimer la
  ligne, puis efface ces fichiers un par un. Elle ne balaye PAS le
  stockage : un fichier qu'aucun dossier supprime ne reference pas ne
  peut pas etre touche, meme par accident.

  C'est la difference avec le script de nettoyage des orphelins utilise
  en septembre : celui-la partait du disque et demandait a la base ce
  qu'il fallait garder. Si la base avait ete injoignable, il aurait pris
  tout le stockage pour des orphelins (d'ou son garde-fou). Ici le
  raisonnement est inverse, et le risque n'existe pas.


=======================================================================
  3. LES DEUX REGLAGES — a relire AVANT de deployer
=======================================================================

  Ils sont en haut du fichier de migration, bien commentes.

  a) LIMITE   (ligne « private const LIMITE »)

       null                    tous les dossiers. C'est le reglage
                               livre, et le bon cas si aucun dossier
                               REEL n'a encore ete depose.

       '2026-11-03 08:00:00'   seulement les dossiers crees avant ce
                               moment. A utiliser si de vrais dossiers
                               sont deja arrives : ceux-la seront
                               epargnes. Heure du SERVEUR, en UTC — le
                               Togo est en UTC, c'est donc votre heure.

  b) AVEC_LES_CANDIDATURES   (ligne « private const AVEC_LES_CANDIDATURES »)

       false                   livre ainsi. Les candidatures publiques
                               (admissions deposees sans compte) ne sont
                               pas touchees.

       true                    les retire aussi, avec leurs voeux, leurs
                               pieces et leurs fichiers.

  /!\ Modifiez le fichier AVANT de l'envoyer sur le serveur, ou
      modifiez-le sur le serveur AVANT de lancer migrate. Une fois la
      migration passee, elle ne repassera plus.

  4. COMBIEN DE DOSSIERS SONT CONCERNES — a verifier d'abord
=======================================================================

SITE=/home/gysj7444/dematerialisation.univ-kara.org
PHP="/opt/alt/php83/usr/bin/php -c $SITE/php.ini"
ART="$PHP $SITE/artisan"
DB_NAME=$(grep '^DB_DATABASE=' $SITE/.env | cut -d= -f2 | tr -d '"')
DB_USER=$(grep '^DB_USERNAME=' $SITE/.env | cut -d= -f2 | tr -d '"')
STAMP=$(date +%Y%m%d-%H%M)
echo "SITE=$SITE DB=$DB_NAME USER=$DB_USER STAMP=$STAMP"

  # Aucune des quatre valeurs ne doit etre vide.

mysql -u "$DB_USER" -p -t "$DB_NAME" -e "
SELECT sr.id, sr.category, sr.status, sr.created_at,
       s.nom, s.prenom, u.numero_identifiant,
       (SELECT COUNT(*) FROM request_files rf WHERE rf.student_request_id = sr.id) AS pieces
FROM student_requests sr
JOIN students s ON s.id = sr.student_id
JOIN users u    ON u.id = s.user_id
ORDER BY sr.created_at;"

  Relisez la liste. Si un dossier REEL y figure, reglez LIMITE
  (section 3a) pour l'epargner.
