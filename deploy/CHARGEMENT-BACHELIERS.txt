  DEMATERIALISATION — UNIVERSITE DE KARA
  Charger le fichier national des bacheliers
  17 novembre 2026
=======================================================================

  Le fichier : bacheliers.csv — 173 890 lignes, toutes les promotions
  de 1975 a 2026 (dont 61 697 pour 2026).

  POURQUOI L'ECRAN D'IMPORT NE PASSAIT PAS
    - Il lit tout le fichier en memoire puis interroge la base 3 a 4
      fois PAR LIGNE : plus d'un demi-million de requetes dans une page
      web limitee a deux minutes.
    - Il attendait « sexe » et « serie_bac » ; le fichier porte
      « code_sexe » et « code_serie » : chaque ligne etait rejetee.
    - Il reconnaissait une fiche a son n° de table seul. Or ce numero est
      reattribue a chaque session du bac : les promotions se seraient
      ecrasees entre elles.

  LA SOLUTION : une commande, en ligne de commande, sans limite de temps.
  Elle lit le fichier ligne a ligne, reconnait les colonnes par leur NOM
  (l'ordre n'importe pas), comprend le Windows-1252 et les « NULL »
  ecrits en toutes lettres, et insere par paquets de 500.

  Essai sur le vrai fichier, base jetable sur l'ordinateur :
    analyse a blanc   :  7 s
    chargement        : 32 s pour 173 876 fiches
    relance           :  6 s, 0 fiche ajoutee (aucun doublon)
    accents           : intacts, aucun caractere casse
    connexion simulee : fiche retrouvee en 2,6 ms (index sur la date)


=======================================================================
  1. LE NUMERO DE SUIVI : c'est la colonne « id »
=======================================================================

  Ce n'est pas une supposition — l'erreur a deja ete faite une fois sur
  les anciens etudiants. C'est verifie :

    760 vrais numeros de suivi d'anciens etudiants (base.csv, « vrai »)
    se retrouvent parmi les « id » du fichier des bacheliers.
    Sur ces 760 paires : 760 meme nom ET meme date de naissance.

    Temoin : avec les anciens numeros FAUX (colonne « test »), 336
    paires se forment — et AUCUNE ne designe la meme personne.

  Chacun garde donc son numero du bac a l'universite : l'« id » du
  fichier EST le numero de suivi. D'ou l'option --id-est-le-suivi
  ci-dessous. Sans elle, le numero de suivi reste vide.

  2. CE QUE LE FICHIER CONTIENT DE DOUTEUX
=======================================================================

  Ecartees (14) — ces personnes ne pourront pas se connecter :
     12  prenom vide
      2  lieu de naissance vide
     -> a ajouter a la main (Reference > Identites) si elles se
        presentent. La liste est dans le fichier des rejets.

  Chargees, mais signalees (128) :

         la fiche la plus recente.
     27  date de naissance invraisemblable : la personne ne pourra pas
         prouver son identite tant qu'elle n'est pas corrigee.
     15  annee de bac invraisemblable (« 20219 », « 80740 »…) :
         l'annee est laissee vide.

  5. CE QUI CHANGE AILLEURS
=======================================================================

  - LISTES PDF des demandes (Demandes > Exporter > PDF) : la premiere
    colonne est desormais le N° de suivi, pour valider les dossiers
    dans l'autre systeme.

  - EXPORT EXCEL des bacheliers (Reference > Identites) : refuse
    au-dela de 20 000 fiches, avec un message. Le generer dans une page
    web epuiserait la memoire et l'ecran resterait blanc.

  - IMPORT PAR L'ECRAN : toujours la pour les petits fichiers. Il
    comprend maintenant aussi le format de l'extraction (code_sexe,
    code_serie, NULL), et ne confond plus deux promotions au meme
    numero de table.

  - SAUVEGARDES : la base passe d'environ 1 Mo a plusieurs dizaines de
    Mo. Avec 14 jours de retention, prevoir quelques centaines de Mo —
    sans consequence avec l'espace du VPS.

  - LOGO du menu : version complete, nom en blanc, sans pave blanc.
